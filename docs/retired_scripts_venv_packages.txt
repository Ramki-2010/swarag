REASON FOR RETIREMENT
---------------------
Swarag contained two virtual environments sharing the name
my_virtual_env_swarag -- one at the repository root, one under scripts/.
Two environments with the same name is an operational hazard, and it had
already caused documentation drift: .ai/agent_spec.md RULE 11 and
.ai-memory/debug-playbook.md both pointed at the scripts/ copy, while recent
work (including the canonical Q-001B-A run of 2026-08-17) used the root copy.

This environment is NO LONGER REQUIRED BY ACTIVE SWARAG WORKFLOWS. That is
not the same claim as "unnecessary" or "never used" -- see below.

The core analysis stack is version-identical between the two environments
(numpy 2.2.6, librosa 0.11.0, scipy 1.15.3, soundfile 0.13.1, numba 0.63.1,
matplotlib 3.10.8), so retiring this environment does not affect any research
result, and does not invalidate the features_v12 cache validated in L-051.

HISTORICAL USE (do not misread as "unused")
-------------------------------------------
This environment held 38 packages the root environment does not, centred on
mirdata 1.0.0 and its transitive dependencies (boto3/botocore/s3transfer,
azure-storage-blob, google-cloud-storage, smart_open, paramiko, cryptography),
plus MIDI tooling (mido, pretty-midi), h5py, openpyxl, invoke and PyYAML.

mirdata WAS genuinely used during early project setup to explore the Saraga
Carnatic dataset as a data source -- see scripts/archive/test_saraga_load.py,
which records that the project subsequently moved to its own seed_carnatic
dataset. requirements.txt lists mirdata as commented-out and Optional.

As of the 2026-08-17 audit, no ACTIVE workflow imports any of the 38 packages.
The only committed importer is the archived, explicitly deprecated script named
above. Grep over committed code cannot prove these packages were never used
ad hoc from a shell or notebook; that possibility is not established either way.
